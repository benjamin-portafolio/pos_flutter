## Flujo implementado

presentation
  -> application/commands
  -> crea SyncEvent
  -> application/sync/LocalEventStore
  -> data/local/drift guarda events y event_refs
  -> application/sync/EventProcessor.apply(event)
  -> handler idempotente
  -> puerto de proyeccion
  -> adaptador Drift actualiza tabla local/proyeccion
  -> repository mapea Drift a dominio
  -> presentation observa repository

## Alcance actual

- El flujo completo implementado es `espacio_creado`.
- `Agregar mesa` existe visualmente, pero no tiene flujo funcional.
- El comando de `espacio_creado` guarda y aplica el evento localmente.
- La sincronizacion remota esta separada en `SyncOrchestrator` y solo se inicia al arrancar en modo `server_sync`.
- Hay envio de pendientes por HTTP push, pull incremental y listener websocket.
